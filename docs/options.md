## smol\.emptyHwdb\.enable

Whether to enable shipping an empty udev hardware database\. ` /etc/udev/hwdb.bin ` is 13\.21
MiB of vendor and model properties for USB devices, PCI cards, keyboards,
pointing devices, accelerometers and the rest\. A Nitro instance has an
ENA adapter and an NVMe disk, neither of which needs a lookup table to be
recognised\.

There is no NixOS option for this: ` services/hardware/udev.nix ` builds
` hwdb.bin ` from the ` hwdb.d ` files of udev and every package in
` services.udev.packages `, and wires it to ` environment.etc ` with no
switch\. The override replaces the file with a database generated the same
way from a single placeholder entry, so it is a valid database that
matches nothing rather than an empty file udev has to cope with\.

Measured saving (appliance track, EC2): 13\.21 MiB closure, 16\.00 MiB
raw image, ledger \#39\.
Trade-offs: udev applies no hardware properties\. On a machine with
peripherals that means wrong keyboard mappings, missing device names and
no model metadata; on a virtual machine with two virtual devices it means
nothing\.
Source: [https://gist\.github\.com/siraben/a8fce9912891d85e1ec3cf74081ba4f6](https://gist\.github\.com/siraben/a8fce9912891d85e1ec3cf74081ba4f6),
backlog item ` s9 `

## smol\.leanImage\.enable



Whether to enable building the disk image without the things the stock EC2 image builder
puts in it by default and never measures\.

The closure is not the image\. Every experiment in this lab until now
measured ` system.build.toplevel `, and the raw VHD stayed about 900 MiB
larger than that number could explain\. Reading
` nixos/lib/make-disk-image.nix ` says why:

 - ` copyChannel ` defaults to ` true `, so the image carries a complete copy
   of the nixpkgs source tree as a nix channel\. It is added to the
   image’s own store through ` basePaths `, so it never appears in the
   system closure and no measurement here could see it\. An appliance with
   no Nix has no use for a channel\.
 - ` diskSize ` is forced to a fixed 4096 MiB by
   ` maintainers/scripts/ec2/amazon-image.nix `, where make-disk-image’s own
   default is ` "auto" `, which sizes the filesystem to its contents plus
   ` additionalSpace `\.

Both are changed here by extending ` image.modules.amazon `, which is a
` deferredModule ` and therefore merges with nixpkgs’ own definition\. The
override applies only inside the image evaluation; the system
configuration is untouched\.

Measured saving (appliance track, EC2): **544\.14 MiB of raw image**,
1400\.35 to 856\.21 MiB, 38\.9%, with no change to the closure at all\.
Boot time also fell from 36\.4s to 14\.3s, ledger \#25\.
Trade-offs: no ` nix-channel ` on the target, which matters only on the
mutable track, and a root filesystem sized to its contents rather than to
4 GiB\. ` growpart ` still grows the partition to fill whatever EBS volume
the instance is launched with, so the running machine is unaffected\.
Requires: nothing\.
Source: found by lab, exp \#022, by reading the image builder rather than
the closure
\.

## smol\.minimalInitrdModules\.enable



Whether to enable cutting ` boot.initrd.availableKernelModules ` down to what a Nitro
instance can actually have\. The stock list is 35 modules: IDE and SATA
controllers, USB host controllers of three generations, MMC, PS/2
keyboards and eight separate USB HID drivers\. A Nitro instance has an
NVMe disk and an ENA adapter\.

` ena ` is not in this list and must not be: ` smol.noKernelModules ` pins it
through ` boot.initrd.kernelModules `, which force-loads it rather than
leaving it for a udev probe that will never happen\.

Measured saving (appliance track, EC2): **not accepted**\. Ledger \#42
measured 1\.41 MiB closure and 4\.00 MiB image, and gate 1 panicked: the
test VM mounts its nix store over virtio and 9p, and this list removes
the modules for both\. Making it pass would need an escape hatch like
` smol.minimalSystemPackages.extra `, which is a lot of machinery for 1\.41
MiB, inside BRIEFING §9’s stop-criterion band\.

Kept, not enabled, because the finding is worth more than the saving:
**the initrd module list has to satisfy both gates**, exactly like the
kernel config in experiment 12\. The initrd’s 24\.77 MiB is its systemd
userland, not its modules, which are 2\.7 MiB in total\.
Trade-offs: this initrd can reach an NVMe root filesystem and nothing
else\. An instance type with SATA or IDE storage will not boot, and the
symptom is a kernel panic at root mount rather than a message about a
missing module\. Narrower than ` smol.noKernelModules ` and for the same
reason\.
Requires: nothing, but it only makes sense alongside
` smol.noKernelModules `\.

## smol\.minimalSystemPackages\.enable



Whether to enable replacing ` environment.systemPackages ` with an explicit list of what this
appliance actually runs\. A stock EC2 NixOS has 57 packages on the system
path, among them ` man-db `, ` bind `, ` nano `, ` shared-mime-info `,
` hicolor-icon-theme `, ` sound-theme-freedesktop `, ` fontconfig `,
` cryptsetup `, ` lvm2 `, ` bcache-tools `, ` kexec-tools ` and GRUB’s install
tools\. None of them has a caller on a headless machine that is replaced
rather than reconfigured\.

This is ` mkForce ` on the whole list rather than a set of options, which
BRIEFING §5 asks to avoid\. The reason is that the contributions come from
a dozen modules with no common switch, and filtering the list in place
is self-referential and makes the module system recurse\. The explicit
list is also the honest form: it says what the appliance needs rather
than what it happens not to have removed\.

Services are unaffected\. ` sshd `, ` dhcpcd ` and ` dbus ` reference their own
packages from their unit definitions, so they keep working whether or not
the package is on anyone’s PATH\.

Measured saving (appliance track, EC2): 57\.32 MiB closure, 86\.03 MiB
raw image, ledger \#31\. 57 packages down to 16\. ` smol.minimalSystemPackages.fullCoreutils = false ` takes a further 12
MiB, ledger \#41\.
Trade-offs: no ` man `, no editor, no ` host ` or ` dig `, no LVM, LUKS or
bcache tooling, and the bootloader cannot be reinstalled from the running
system\. Anything that shells out to one of these breaks, which on this
image means checking the EC2 boot path and the verification contract,
both of which gate 1 covers\.
Requires: nothing\.
Source: [https://natkr\.com/2026-06-19-nixos-but-smol/](https://natkr\.com/2026-06-19-nixos-but-smol/), backlog item ` n5 `
\.

## smol\.nitroKernel\.enable



Whether to enable a kernel configured for a Nitro instance instead of for arbitrary
hardware\. The stock NixOS kernel ships a 145\.17 MiB module tree, of which
115 MiB is ` drivers `: 15 MiB of media, 13 of GPU, 15 of sound, and a long
tail of buses and sensors that no virtual machine has ever had\.

What an EC2 Nitro instance actually needs is ENA for the network, NVMe
for storage and ext4 for the root filesystem\. Those are built in rather
than left modular, so nothing has to be loaded at runtime to reach the
root device\.

virtio and 9p stay built in too, and that is not an oversight: gate 1
boots this same kernel under QEMU, so a kernel that only works on Nitro
cannot be tested locally\. One kernel has to satisfy both gates\.

Measured saving (appliance track, EC2): TBD, ledger \#TBD\.
Trade-offs: no sound, no graphics, no USB, no wireless, no infiniband, no
industrial IO, no sensors, and a short list of filesystems\. On an
instance type with different hardware this kernel may not boot at all,
which is why it is named for Nitro rather than for EC2\.
Requires: nothing, but ` smol.noKernelModules ` requires this\.

## smol\.noDuplicateSystemd\.enable



Whether to enable building ` util-linux ` without systemd support, so the image stops
carrying a second systemd\.

A stock image has both ` systemd ` at 63\.02 MiB and
` systemd-minimal-libs ` at 22\.26 MiB\. The second one is there because
` agetty ` in ` util-linux-bin ` links against libsystemd, and nixpkgs builds
that against ` systemdMinimal ` rather than the real systemd to avoid a
dependency cycle: systemd needs util-linux for libmount and libblkid\.

Pointing ` util-linux ` at the full systemd would close that cycle and is
not an option\. Dropping the support removes the second build outright\.

Measured saving (appliance track, EC2): 22\.11 MiB closure, 24\.00 MiB
raw image, ledger \#48\.

Experiments \#18, \#20 and \#47 each found another holder\. ` agetty ` was
only the first; ` libfido2 ` and ` dbus-lib ` came through
` switch-to-configuration ` and left with it in \#45, and ` dbus ` itself and
` pam_timestamp_check ` turned up after that\.

Requires: ` smol.noLastlog `\. util-linux ships its systemd units,
tmpfiles and sysusers fragments in its ` lastlog ` output, and NixOS adds
that output to ` systemd.tmpfiles.packages ` whenever PAM’s lastlog is on\.
Without systemd support the fragment does not exist and the ` etc `
derivation fails to build\.
Source: [https://gist\.github\.com/siraben/a8fce9912891d85e1ec3cf74081ba4f6](https://gist\.github\.com/siraben/a8fce9912891d85e1ec3cf74081ba4f6),
backlog item ` e5 `, and siraben’s warning that a slim systemd must be an
overlay or consumers pull a second full build

## smol\.noFirewall\.enable



Whether to enable turning off the in-guest firewall and relying on the EC2 security group
instead\. On EC2 the security group is already a stateful packet filter
sitting in front of the instance, enforced outside the guest and
unaffected by anything that happens inside it\.

This exists because ` smol.noKernelModules ` needs it: netfilter is
modular, so ` firewall.service ` cannot start once the module tree is
gone\. It is worth having on its own terms, but the measured saving is
small and the reason to enable it is the one that follows\.

Measured saving (appliance track, EC2): 7\.53 MiB closure, ledger \#14\.
Small, as expected: the point of this option is what it unlocks\.
Trade-offs: real, and this is the first strategy in this lab where the
trade-off is about security rather than convenience\. The instance has no
defence of its own\. A misconfigured security group is no longer caught by
a second layer, and anything listening on an unexpected port is reachable
from wherever that group allows\. On a machine whose only listening
service is sshd, behind a group that permits only 22, that is a
defensible position\. It is not a default anyone should inherit without
reading this paragraph\.
Requires: nothing\. ` smol.noKernelModules ` requires it\.
Source: found by lab, exp \#013, where gate 1 caught ` firewall.service `
failing with the module tree removed
\.

## smol\.noKernelModules\.enable



Whether to enable dropping the kernel module tree from the system closure\. The ` toplevel `
carries a ` kernel-modules ` symlink to the full 145\.17 MiB tree, which is
the single largest path in the image and the only reason it is there at
all is so modules can be loaded at runtime\.

An EC2 instance loads what it needs in the initrd, which carries its own
copy of the handful of modules that matter, and then never loads another
one\. The tree behind the symlink is dead weight from the moment the root
filesystem is mounted\.

Measured saving (appliance track, EC2): 152\.93 MiB closure, ledger \#17\.
The largest single saving in this lab, and more than the module tree
itself: the module dependency metadata and firmware go with it\.
Trade-offs: ` modprobe ` can load nothing\. Any hardware or feature not
already force-loaded in the initrd or built into the kernel is
unreachable, permanently, and the symptom is a device that silently does
not appear rather than an error\. This option therefore pins ` ena ` into
the initrd, and it is the strategy most likely to break an instance type
other than the one it was tested on: a type with a different network or
storage adapter needs its driver added to the same list\.
Requires: ` smol.noFirewall `\. Netfilter is modular, so
` firewall.service ` cannot start once the tree is gone, which gate 1
caught in experiment 013\. It also leans entirely on
` boot.initrd.availableKernelModules ` carrying ENA and NVMe, which
` virtualisation/amazon-image.nix ` already arranges\.
Source: [https://natkr\.com/2026-06-19-nixos-but-smol/](https://natkr\.com/2026-06-19-nixos-but-smol/), backlog item ` n7 `

## smol\.noPerl\.enable



Whether to enable replacing the two activation scripts that are written in Perl\.
` setup-etc.pl ` builds ` /etc ` on every boot and ` update-users-groups.pl `
reconciles users and groups; between them they are the reason a stock
NixOS carries a 55\.18 MiB Perl\.

` system.etc.overlay ` mounts ` /etc ` as an overlay instead of populating
it with a script, and ` services.userborn ` does users and groups in a
small C program\.

Measured saving (appliance track, EC2): 58\.00 MiB closure, 68\.00 MiB raw
image, ledger \#46\.

Experiment 37 ran this and saved nothing, because ` install-grub.pl ` is
Perl too and ` switch-to-configuration ` held it\. Experiment 45 removed

## smol\.noPython\.enable



Whether to enable removing the CPython interpreter from an EC2 image\. A stock NixOS EC2
system carries a full 136\.55 MiB CPython for the sake of exactly two

   into a ` /dev/sdX ` symlink on Nitro\.
 - ` ec2metadata ` in ` cloud-utils `, which ships in the same output as

` ec2metadata ` command on the target, which is a convenience for humans
rather than something the system uses\.
Requires: ` smol.noInstallerTools `, which removes the third consumer\.

## smol\.slimSystemd\.enable



Whether to enable building systemd with the features an appliance uses and no others\.
` systemd ` is 63\.02 MiB and the largest path left, and a stock build
carries homed, portabled, importd, repart, sysupdate, vmspawn, oomd,
coredump, cryptsetup, TPM2, FIDO2, qrencode and the remote journal
tooling, none of which this image has a caller for\.

This is a ` nixpkgs.overlays ` entry rather than an override on
` systemd.package `, which is the whole point: an override would leave
every consumer linking the stock build and the image would carry two
systemds instead of one\. It is why the flake never hands a prebuilt
` pkgs ` to ` nixosSystem `, and why gate 1 sets ` node.pkgsReadOnly = false `\.

What stays, and why:

 - ` withAnalyze `, because ` lab/deploy-ec2.sh ` measures boot time with
   ` systemd-analyze ` and the ledger would lose a column without it\.
 - ` withTimedated `, because contract check 6 calls ` timedatectl `\.
 - ` withTimesyncd `, because check 6 is about the clock being synchronised\.
 - ` withLogind `, because SSH sessions are logind sessions\.
 - ` withMachined `, because ` /etc/nsswitch.conf ` lists ` mymachines ` and
   losing the module breaks ` getent `, which is contract check 4\.
 - ` withQrencode `, which looks like the most obviously useless feature on
   a headless server and is not optional: it gates
   ` systemd-bsod.service `, and NixOS puts that unit in the initrd’s list
   unconditionally\. Without it ` initrd-units ` fails to build with
   ` missing .../example/systemd/system/systemd-bsod.service `\. libqrencode
   is small; fighting the unit list is not\.

Measured saving (appliance track, EC2): 36\.98 MiB closure, 46\.00 MiB
raw image, ledger \#36\.
Trade-offs: no coredumps, no systemd-homed, no portable services, no
` systemd-repart `, no TPM2 or FIDO2 unlocking, no remote journal upload\.
Each is a capability a production base image might want; none is
reachable on a machine that is replaced rather than administered\.
Requires: nothing\.
Source: [https://gist\.github\.com/siraben/a8fce9912891d85e1ec3cf74081ba4f6](https://gist\.github\.com/siraben/a8fce9912891d85e1ec3cf74081ba4f6),
backlog item ` s1 `
\.

boolean



*Default:*

```nix
false
```



*Example:*

```nix
true
```

 - [modules/smol/slim-systemd\.nix](https://github.com/wearetechnative/smol-nixos-base-image-nivis-ec2-experiment/blob/main/modules/smol/slim-systemd.nix)
