## smol\.noAmazonInit\.enable

Whether to enable removing ` virtualisation.amazon-init `, the service that reads EC2
user-data and, when it looks like a NixOS configuration, applies it with
` nixos-rebuild switch `\. Because it does, it puts ` nixos-rebuild ` on the
service’s PATH, which is what keeps a full CPython interpreter in an
image that has no other use for one\.

Measured saving (appliance track, EC2): 101\.10 MiB closure,
110\.03 MiB raw image, ledger \#4\.
Trade-offs: user-data is no longer executed\. An instance can no longer be
reconfigured at launch, which is the whole point of the appliance track
but removes a mechanism a production fleet may depend on\. SSH key
injection is unaffected: that is ` ec2-metadata-fetcher `, a different
service\.
Requires: nothing, but ` smol.noInstallerTools ` requires this\.
Source: found by lab, exp \#004, after exp \#003’s dependency guard caught
that ` system.disableInstallerTools ` alone does not remove ` nixos-rebuild `
\.



*Type:*
boolean



*Default:*

```nix
false
```



*Example:*

```nix
true
```

## smol\.noDefaultPackages\.enable



Whether to enable emptying ` environment.defaultPackages `, the set NixOS installs on every
system whether or not anything asks for it: perl, rsync, strace and
friends\. natkr’s second step\.

Measured saving (appliance track, EC2): 3\.39 MiB closure, ledger \#11\.
Far smaller than natkr’s ISO context suggests, because most of what
` defaultPackages ` pulls in is also pulled in by something else on an EC2
system\. perl in particular survives it; see BACKLOG\.md item ` n8 `\.
Trade-offs: none of those commands exist on the target\. Anything shelling
out to one of them breaks, which on this image means checking that
nothing in the EC2 boot path does\. The verification contract uses only
coreutils, systemd and util-linux, all of which arrive by other routes\.
Requires: nothing\.
Source: [https://natkr\.com/2026-06-19-nixos-but-smol/](https://natkr\.com/2026-06-19-nixos-but-smol/), backlog item n2
\.

## smol\.noFlakeRegistry\.enable



Whether to enable dropping the system flake registry\. A flake-built NixOS pins its own
nixpkgs into ` /etc/nix/registry.json `, which drags the entire nixpkgs
source checkout into the system closure so that ` nix run nixpkgs#... `
resolves offline\. An appliance has no Nix and never resolves a flake
reference, so the registry buys nothing and costs a fifth of the closure\.

Measured saving (appliance track, EC2): 199\.75 MiB closure,
504\.12 MiB raw image, ledger \#2\.
Trade-offs: ` nix registry list ` is empty and a bare ` nixpkgs# ` reference
no longer resolves on the target\. Irrelevant without Nix, and a mutable
target can set the registry at runtime\.
Requires: nothing\.
Source: found by lab, exp \#002, from ` nix why-depends ` on the baseline
\.



*Type:*
boolean



*Default:*

false

## smol\.noInstallerTools\.enable



Whether to enable removing ` nixos-rebuild `, ` nixos-generate-config `, ` nixos-install `,
` nixos-enter ` and ` nixos-option ` from ` environment.systemPackages `
through ` system.disableInstallerTools `\.

On its own this saves nothing: ` virtualisation.amazon-init ` holds a
second reference to ` nixos-rebuild `, so the tool and its CPython stay in
the closure\. It therefore asserts ` smol.noAmazonInit `\.

Measured saving (appliance track, EC2): 12\.34 MiB closure, ledger \#5\.
Far less than the 136\.55 MiB CPython it was aimed at: ` amazon-ec2-utils `
holds a second reference to the interpreter through a udev rule\. See
BACKLOG\.md item ` e8 `\.
Trade-offs: the target cannot rebuild itself\. That is the definition of
the appliance track, where updates replace the AMI, but it makes the
system unusable on the mutable track\.
Requires: ` smol.noAmazonInit `, and the appliance track\.
Source: found by lab, exp \#003 and \#005
\.



*Type:*
boolean



*Default:*

```nix
false
```



*Example:*

```nix
true
```

## smol\.noPython\.enable



Whether to enable removing the CPython interpreter from an EC2 image\. A stock NixOS EC2
system carries a full 136\.55 MiB CPython for the sake of exactly two
scripts, neither of which the machine needs to boot or to be managed:

 - ` ebsnvme-id ` in ` amazon-ec2-utils `, run by
   ` 70-ec2-nvme-devices.rules ` to turn an EBS volume’s attachment name
   into a ` /dev/sdX ` symlink on Nitro\.
 - ` ec2metadata ` in ` cloud-utils `, which ships in the same output as
   ` growpart ` and is pulled in with it by ` growpart.service `\.

Both are stripped, along with the two udev rules that call the first\.
Everything else stays: ` ec2udev-vbd ` and ` ec2nvme-nsid ` are shell,
` growpart ` itself is shell, and the ` queue/io_timeout ` tuning in the NVMe
rules is reliability rather than naming and must not be lost\.

Measured saving (appliance track, EC2): 136\.87 MiB closure,
137\.00 MiB raw image, ledger \#9\. Boot time also fell from about 40s to
38\.1s, the first change in this lab to move it measurably\.
Trade-offs: no ` /dev/sdX ` or ` /dev/xvdX ` symlink for an NVMe-backed EBS
volume, so anything addressing a volume by its attachment name breaks\.
The root filesystem is found by label and does not care\. No
` ec2metadata ` command on the target, which is a convenience for humans
rather than something the system uses\.
Requires: ` smol.noInstallerTools `, which removes the third consumer\.
Source: found by lab, exps \#005, \#007 and \#008, by following
` nix why-depends ` to the interpreter four times over
\.



*Type:*
boolean



*Default:*

```nix
false
```



*Example:*

```nix
true
```

*Declared by:*
 - [modules/smol/no-python\.nix](https://github.com/wearetechnative/smol-nixos-base-image-nivis-ec2-experiment/blob/main/modules/smol/no-python.nix)



## smol\.noSsmAgent\.enable



Whether to enable removing the AWS Systems Manager agent, which
` virtualisation/amazon-image.nix ` enables by default\. It is a Go binary
of roughly 110 MiB, and it exists to give Session Manager access and
inventory reporting to instances that are managed through SSM\.

Measured saving (appliance track, EC2): 110\.33 MiB closure,
114\.00 MiB raw image, ledger \#6\.
Trade-offs: no Session Manager shell, no SSM inventory, no Run Command,
no patch reporting\. If the production fleet is managed through SSM this
belongs in neither profile; the lab verifies over SSH and never uses it\.
Requires: nothing\.

## smol\.profile



Bundle of accepted size-reduction strategies to enable\.

` none ` is the untouched baseline\. ` safe ` enables every accepted
strategy whose trade-offs are acceptable for a production base image\.
` aggressive ` adds the strategies that cost functionality or
supportability\. Membership is defined in ` modules/smol/profiles.nix `
and every member has measured numbers in its own option description\.



*Type:*
one of “none”, “safe”, “aggressive”



*Default:*

```nix
"none"
```

*Declared by:*
 - [modules/smol](https://github.com/wearetechnative/smol-nixos-base-image-nivis-ec2-experiment/blob/main/modules/smol)



## smol\.track



Which track this system targets (BRIEFING §3)\. ` appliance ` has no Nix
on the target, an immutable ` /etc ` and no switch-to-configuration;
updates replace the AMI\. ` mutable ` keeps Nix and in-place updates\.
Strategies incompatible with a track assert against it\.



*Type:*
one of “appliance”, “mutable”
