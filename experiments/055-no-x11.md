# 055: no-x11

- **Track:** appliance
- **Contract:** 1 (the whole contract reruns; nothing in it is graphical)
- **Module:** `smol.noX11`
- **Source:** found by lab, exp #55, from `FLOOR.md`'s referrer table

## Hypothesis

A headless EC2 image carries an X11 cluster of 7.62 MiB. The referrer dump
says it arrives through three unrelated defaults:

- `xauth-1.1.5` is referenced by `/etc/pam.d`, because
  `nixos/modules/programs/shadow.nix` sets
  `security.pam.services.su.forwardXAuth = true`, which puts `pam_xauth.so`
  in the `su` stack. `xauth` pulls `libX11`, `libXext`, `libXmu`, `libXt`,
  `libXau` and `libXdmcp`.
- `libx11` is also referenced by `dbus-1.16.2-lib`, built with
  `x11Support` for the X11 autolaunch transport.
- `fontconfig-2.18.3` comes from `fonts.fontconfig.enable`, which defaults
  to true and writes an etc entry whatever else is installed.

There is no X server, no `DISPLAY` and no graphical session. `su` is only
ever reached over SSH, X11 forwarding is off in sshd, and dbus autolaunch
needs a display to attach a session bus to.

## What changed

[`modules/smol/no-x11.nix`](../modules/smol/no-x11.nix): all three at once,
because they are one fact about the machine rather than three strategies.

```nix
security.pam.services.su.forwardXAuth = lib.mkForce false;
fonts.fontconfig.enable = false;
dbus = prev.dbus.override { x11Support = false; };
```

The dbus override composes with the one `smol.noDuplicateSystemd` already
applies: a later overlay's `prev.dbus` is the earlier overlay's result, and
`.override` merges arguments rather than replacing them.

## Numbers

| measure    | before | after  | delta       |
| ---------- | ------ | ------ | ----------- |
| closure    | 319.99 | 313.04 | 6.94, 2.2%  |
| image, raw | 452.11 | 440.11 | 12.00, 2.7% |

Paths that left: `xauth`, `libx11`, `libxcb`, `libxext`, `libxmu`, `libxt`,
`libxau`, `libxdmcp`, `fontconfig` and its two etc derivations.

## Gate 1, local

Pass, 10 of 10.

## Gate 2, EC2

Pass. Boot 14.07s.

Teardown: instance, AMI and snapshot destroyed; `STATE.md` live table empty.

## Decision

Accepted. The image saving is nearly twice the closure saving, which keeps
happening since #25 and is the reason the protocol measures both.

## Surprises

The cost was in build time, not in risk: the dbus override rebuilt QEMU
again, the same hour that #48 paid, because `make-disk-image` runs the image
build inside a QEMU VM. Any overlay touching dbus pays it.
